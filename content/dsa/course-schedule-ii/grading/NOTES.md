# Grader notes: Course Schedule II

Any valid order passes. When an order exists, the tests check that the array has one entry per course, that every entry is a real course and appears once, and that for every pair the prerequisite comes strictly before its course. When no order exists, the array must be empty; a partial order fails.

Tests cover: the sample (the order of Example 1 or any other valid one, a loop of two next to a free course, three courses with no pairs); a course that lists itself, alone and inside an otherwise fine plan; courses that appear in no pair still being listed; chains with exactly one valid order (listing courses in the order a depth-first search finishes them gives it backwards and fails); two routes to the same course; a loop that a search from course 0 never reaches, and a loop next to an orderable part (returning that part alone fails); repeated pairs, with and without a loop; thirty seeded random plans that follow a hidden order, each checked again with one pair reversed (empty); and three plans of 100,000 courses: a chain numbered upwards (each course needs the one numbered below it), a chain numbered downwards (course 99,999 comes first), and the downward chain ending in a loop of courses 0 and 1.

Each large test has a limit of 1,000 ms (3x is 3,000 ms). The reference, Kahn's algorithm with the answer array as the queue, took 10 to 16 ms per large test on a cold JVM, including the test's own check of the order. The naive solution appends every ready course in a pass over all pairs and repeats until a pass adds nothing; a chain adds one course per pass, so it timed out on all three large tests even with the limit raised fivefold (5,000 ms). The downward chains are there for a faster-looking variant: sweeping the courses from 0 upwards with in-place counts, so a course freed earlier in a sweep is added in the same sweep, finishes the upward chain in one sweep (35 ms) but adds one course per sweep on a downward chain and timed out on both. The walkthrough's recursive depth-first search overflows the call stack on the upward chain, where the search from course 0 follows every course.
