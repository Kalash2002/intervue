# Grader notes: Course Schedule II

Any valid order passes. When an order exists, the tests check that the array has one entry per course, that every entry is a real course and appears once, and that for every pair the prerequisite comes strictly before its course. When no order exists, the array must be empty; a partial order fails.

Tests cover: the sample (the order of Example 1 or any other valid one, a loop of two next to a free course, a single course); a course that lists itself, alone and inside an otherwise fine plan; courses that appear in no pair still being listed; chains with exactly one valid order (listing courses in the order a depth-first search finishes them gives it backwards and fails); two routes to the same course; a loop that a search from course 0 never reaches, and a loop next to an orderable part (returning that part alone fails); repeated pairs, with and without a loop; thirty seeded random plans that follow a hidden order, each checked again with one pair reversed (empty); and two plans of 100,000 courses: one chain where each course needs the one before it, and the same chain ending in a loop of the last two courses.

Each large test has a limit of 1,000 ms (3x is 3,000 ms). The reference, Kahn's algorithm with the answer array as the queue, took 11 to 21 ms per large test on a cold JVM, including the test's own check of the order. The naive solution appends every ready course in a pass over all pairs and repeats until a pass adds nothing; a chain adds one course per pass, so it timed out on both large tests even with the limit raised fivefold (5,000 ms). The walkthrough's recursive depth-first search overflows the call stack on both large tests.
