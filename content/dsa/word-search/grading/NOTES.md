# Grader notes: Word Search

Every test also checks that the grid holds its original letters after the call, since the statement allows changing it only during the search. Tests cover: the sample, a word blocked only by a diagonal step (a version that allows diagonals finds it and fails), cells needed twice (`qq` on a one-cell grid and `tet` on the sample grid, which a letter-count check alone already rejects, and `bab` on `["abz", "zzb"]`, where the grid has enough of every letter but the `a` touches only one `b`, so a version that never marks visited cells steps back onto that `b` and fails even with a count check), a single cell that matches and one that does not, marks cleared after a dead end (`["mom", "omm"]` with `mmo`: a version that marks cells but never unmarks them leaves the dead ends from the first `m` cells marked when the search starts from the top-left, and so blocks the only trace from the bottom-right `m` and answers false), a word longer than the number of cells, a trace through all twelve cells of the sample grid, and the longest word (16 letters) laid along two rows of a seeded 8 by 8 grid of the letters a to c.

The large test is a seeded 8 by 8 grid of the letters a to c and a seeded 16-letter word of the same letters that is not in it; the reference and the naive agreed on `false`. The limit is 100 ms (3x is 300 ms). The naive solution, the walkthrough's brute force, walks every path of 16 cells and compares the letters only when a path is complete: 1,266 ms in a cold scratch run. The reference stops a trace at its first wrong letter: about 0.1 ms in the same run.
