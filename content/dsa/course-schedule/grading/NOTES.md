# Grader notes: Course Schedule

Tests cover: the sample (a plan that works and a loop of three); a course that lists itself, alone and inside an otherwise fine plan; no pairs at all; a loop of two next to free courses; two routes to the same course (a search that treats any course seen before as a loop fails these); a loop among courses that a search starting only at course 0 never reaches; repeated pairs, with and without a loop; thirty seeded random plans that follow a hidden order (true), each checked again with one pair reversed (false); and three plans of 100,000 courses: a chain numbered upwards (each course needs the one numbered below it), a chain numbered downwards (course 99,999 comes first), and the downward chain ending in a loop of courses 0 and 1.

Each large test has a limit of 1,000 ms (3x is 3,000 ms). The reference, Kahn's algorithm over arrays, took 10 to 19 ms per large test on a cold JVM. The naive solution takes every ready course in a pass over all pairs and repeats until a pass frees nothing; a chain frees one course per pass, so it timed out on all three large tests even with the limit raised fivefold (5,000 ms). The downward chains are there for a faster-looking variant: sweeping the courses from 0 upwards with in-place counts, so a course freed earlier in a sweep is taken in the same sweep, finishes the upward chain in one sweep (22 ms) but frees one course per sweep on a downward chain and timed out on both. The walkthrough's recursive depth-first search overflows the call stack on the upward chain, where the search from course 0 follows every course.
