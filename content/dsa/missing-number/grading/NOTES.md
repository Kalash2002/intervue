# Grader notes: Missing Number

Same rule as the classic version (n distinct numbers from 0 to n, one missing), with one change: n goes up to 10^5 instead of 10^4, so that the brute force can be timed and the sum of 0 to n passes `Integer.MAX_VALUE` (from n = 65,536 on). The classic asks for constant extra memory in its follow-up; here the Follow-up asks for that and for leaving `nums` unchanged. No test can measure memory or see a sort of the caller's array, so a table of flags, a hash set and sorting in place all pass. The answer is a single `int`, so there is only one correct output.

Tests cover: the sample (`[4, 7, 1, 0, 6, 2, 3]` gives 5; `[3, 5, 1, 4, 2]` gives 0; `[0]` gives 1, n itself); `[1]`, the other one-value array; 0 or n missing from shuffled arrays of 10 to 12 values; a missing number in the middle of shuffled arrays of 6 to 13 values; arrays in increasing and in decreasing order; every array of 1 to 7 values in every order, 46,232 calls; 300 seeded random arrays of 1 to 2,000 values, fully shuffled, with the missing number anywhere; four large arrays whose sums pass the `int` range, at n = 46,341, 65,536, 80,264 and 10^5; and the timed test. The expected values of the generated arrays are known by construction.

The traps the walkthrough and hints name, each run as a scratch variant: a table of n flags instead of n + 1 fails all 8 tests with an index out of bounds at the value n; sorting and returning the first position whose value is not its index, with nothing for the case where n is missing, fails 4 (the sample, the 0-or-n test, the small cases and the random arrays); `n * (n + 1) / 2` in `int` fails the large-sums test, which has three arrays with n from 46,341 to 80,264, where the halved `int` product is off by 2^31; and an XOR that starts from 0 instead of n fails all 8. Correct variants that pass everything: the walkthrough's table, sorting a copy, sorting in place, a `HashSet`, the two sums added in `int` with wrap-around, and the formula in `long`.

The naive solution tries each number from 0 up with a scan that stops at the first match, and times out on the timed test at the limit and at 3x. That test has 8 fully shuffled arrays of 10^5 values, each with the missing number at a random place in the middle third of the range, so the search does between n²/6 and n²/3 comparisons per array whether it tries the numbers from 0 up or from n down, and whichever end of the array it scans from. The limit is 400 ms; the reference took 13 to 26 ms over six cold runs, almost all of it building the arrays, and the naive 5,704 ms with the limit raised 20 times. The slower variants the walkthrough names time out too, each at 4.5 times the limit or more: trying the numbers from n down (5,670 ms), scanning the array from its end (5,413 ms), both at once (5,824 ms), and a scan that counts every copy instead of stopping (over 6,000 ms). The faster approaches the walkthrough names pass inside the limit at 1x: the table took 18 ms, sorting a copy 60 ms, sorting in place 101 ms and a `HashSet` 106 ms.
