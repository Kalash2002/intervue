# Grader notes: Plus One

Same sizes and rules as the classic version (1 to 100 digits, most significant first, no leading zeros except `[0]`); only the class and method names are this pack's. The statement lets a solution change `digits` and return it, or return a new array, so the tests compare only the returned array, digit by digit and by length, and show the input as it was before the call. The result is a single number, so there is only one correct output.

Tests cover: the sample (`[5, 8, 0, 6]`, where only the last digit changes; `[3, 9, 9, 9]`, where three 9s carry into the 3; six 9s, which grow to seven digits); the single digits `[0]`, the forced smallest input, `[5]` and `[3]`; inputs where only the last digit changes, including `[1, 0, 0, 0, 0]` and `[9, 9, 9, 8]`; 9s before the end that must keep their value (`[9, 4, 9]`, `[9, 8, 9, 9]`, `[9, 0, 9]`, `[8, 9, 9, 9, 9, 7]`, `[1, 8, 9, 9]`); all nines of length 2, 11 (a counter at its last value) and 100, which grow by one digit; numbers too long for a `long` (`Long.MAX_VALUE` itself, nineteen 9s, a 25-digit number ending in a run of 9s, and a 100-digit number); and 1,000 seeded random numbers of 1 to 100 digits, each ending in a run of 9s of random length, checked against `BigInteger` in the test.

The traps the walkthrough and hints name, each run as a scratch variant: going through a `long` fails the all-nines test, the long numbers and the random numbers (3 of 7); adding one to the last digit with no carry fails 5; carrying through the 9s without stopping at the first digit below 9, so that every digit below 9 goes up, fails 5; turning all nines into zeros without a new, longer array fails 4, as does a new array with the 1 at the wrong end; and the Better's array of n + 1 digits returned without dropping its leading zero fails 6. Two more were run: going through an `int` fails the same three tests as a `long`, and treating a leading 9 as a sign that every digit is 9 fails 4. The walkthrough's Brute force (`BigInteger`) and Better pass.

No naive solution: time is not graded separately for this question (ADR 0008). With at most 100 digits every correct approach finishes in microseconds: the Brute force's `BigInteger` conversions are O(n²) and the Better always makes a full pass and a copy, but at this size neither is meaningfully slower than the reference, which stops at the first digit below 9. The tests keep the default limit; the reference took 30 to 39 ms on the 1,000 random numbers over six cold runs.
