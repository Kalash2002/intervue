# Grader notes: Subsets II

Results are compared after sorting each subset and then the list, because any order is allowed; a subset listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample with its repeats apart (`[3, 1, 3]`: a version that skips a value equal to its neighbour without sorting first never sees the two 3s side by side and lists `[3]` and `[1, 3]` twice), two repeated values, a single value, all values equal (a version that skips repeats by comparing with the previous value at any depth, `i > 0` instead of "not the first choice at this step", loses `[5, 5]` and longer), no repeats at all, values at the limits, eight values with repeats spread out (checked by count: the product of (copies + 1) over the values, with every subset within the available copies and none listed twice, which proves the list is complete), and a large input.

The large input is 24 values, eight each of -7, 0 and 7, in seeded shuffled order: 729 distinct subsets out of 2^24 = 16,777,216 choices of positions. The limit is 400 ms (3x is 1,200 ms). The naive solution, the walkthrough's brute force, tries every choice of positions on a sorted copy and keeps the distinct lists in a set: 3,363 ms in a cold scratch run, past both limits. The reference, which only ever builds distinct subsets, took about 1 ms on the same input.
