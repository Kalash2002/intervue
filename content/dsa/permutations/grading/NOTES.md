# Grader notes: Permutations

The list of orderings is sorted before comparing, but each ordering is compared as returned, because the order inside an ordering is the answer; an ordering listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample, two values, a single value, values at the limits of the range, and four, six and eight values, where the test checks that there are exactly n! orderings, that each holds every value of `nums` exactly once, and that none appears twice, which together prove the list is complete. A version that forgets to clear its "used" mark on the way back finds only the first ordering and fails the sample; a version that adds its working list without copying it ends with equal (usually empty) entries and fails the sample too.

No naive solution: time is not graded separately for this question (ADR 0008). Every correct approach costs at least O(n * n!), the size of the answer. The walkthrough's brute force, which tries all n^n sequences of positions and keeps those without a repeat, took about 750 ms for 8 values in a scratch run against about 25 ms for the reference; a limit at least 8 times the reference (200 ms) would need the naive to take 900 ms or more, so the gap is too small to grade. The largest test (8 values, 40,320 orderings) has a generous 2,000 ms limit only to catch a runaway loop.
