# Grader notes: Pow(x, n)

Same ranges as the classic version (`-100.0 < x < 100.0`, any `int` exponent, an answer between -10^4 and 10^4, and `x` never 0 unless `n` is positive). Two changes: the statement forbids `Math.pow`, `Math.exp`, `Math.log` and their `StrictMath` versions, and it states the tolerance, `|answer - exact| <= 10^-6 * |exact| + 10^-12`, which the classic leaves unsaid. The tolerance is relative because the error of a chain of multiplications grows with the exponent, to about |n| roundings, 2.4 · 10^-7 relative at n = 2^31 and twice that when `1 / x` is rounded first; the absolute floor covers answers that underflow to 0. The check is written as `!(|got - want| <= tolerance)`, so a `NaN` or an infinity fails. The tests cannot tell whether a library power was called: a scratch variant that returns `Math.pow(x, n)`, and one that computes `exp(n · log |x|)` with the sign fixed by hand, both pass. The walkthrough and the statement say why they are ruled out, and a reviewer reading the code sees them.

Expected values come from three places, none of them the reference: values a `double` holds exactly, such as 1.5^9 = 19683/512 and (-2.75)^5, written out; the `double` nearest to a value that is not exact, such as `-1.0 / 27`, 0.0256 and 0.8, whose rounding is far inside the tolerance; and, for inputs too large to write out, `Math.pow`, which is within one unit in the last place of the exact value.

Tests cover: the sample (1.5^9; (-0.5)^-11 = -2048; (-1)^(-2^31) = 1, whose exponent cannot be negated in an `int`); the zero power of four bases, 1 each; small positive powers with exact answers; negative powers, which are reciprocals (8192, -1/1024, 4096, 1/4096, 0.0256, 0.8); negative bases with odd and even exponents, including (-3)^-3; zero to the powers 1, 6 and 1000, which is 0; the smallest `int` exponent with bases 1, -1, 4 and -4 and two bases within 10^-9 of 1 in size; exponents near the `int` limits (bases near 1 to the powers 2^31 - 1, 2 · 10^9, -1.5 · 10^9 and 2147483645, and 0, 1, -1 and 0.5 to the power 2^31 - 1); and 300 seeded random cases with exponents from -3000 to 3000 and bases chosen so that the answer is e^u for u from -9 to 9, checked against `Math.pow`.

The traps the walkthrough and hints name, each run as a scratch variant: negating `n` in an `int`, which leaves the smallest `int` negative, fails the smallest-exponent test, and so does `(long) -n`, which negates before the cast; the same negation with a loop that shifts `n` right until it is 0 never ends on the smallest `int` and times out on the sample and the smallest-exponent test; the recursive version that negates the `int` recurses on the same exponent until the stack overflows (fails the same two); replacing the smallest `int` with the largest, one less, flips the sign for a negative base (fails the same two); ignoring the sign of `n` fails 6 of 9; `exp(n · log x)` without care for the sign, which gives `NaN` for a negative base, fails 8; and treating a zero base as giving 1 fails the zero-base test and the near-limit test. One more was run: multiplying in eight factors per loop round, eight times fewer rounds than the brute force but still linear, fails the three timed tests.

Timing: the sample, `theSmallestIntExponent` and `exponentsNearTheIntLimits` each have a limit of 300 ms (3x is 900 ms); each has at least one exponent of size about 2^31. The reference took 0 to 3 ms on each over six cold runs. The naive solution is the walkthrough's Brute force, one multiplication per unit of the exponent: with the limit raised 20 times it took 4,349 ms on the sample and did not finish the other two in 6,000 ms. The walkthrough's Better, the recursive halving, is O(log |n|) like the reference and passes.
