# Grader notes: Graph Valid Tree

Tests cover: the sample (a tree, and a plan with the right number of pipes but a loop and two cut-off valves); one valve, two valves with no pipe and two valves with one pipe; five pipes for six valves with a loop and a cut-off pair (a solution that checks only the count `n - 1` accepts it and fails); plans with no loop but cut-off valves (a solution that checks only for loops accepts them and fails); a connected plan with one extra pipe; a star and a zigzag line; forty seeded random trees with shuffled labels, pipe order and direction, each checked as is (true), with one extra pipe between two valves not yet joined (false) and with one pipe removed (false); a line of 100,000 valves listed in order (a recursive search overflows the stack here); and the same line listed from the far end with every other pipe reversed, so that neither end of a pipe is reliably the valve with no pipes yet.

Both large tests have a limit of 1,000 ms (3x is 3,000 ms; the rule's line is 4,500 ms). The naive solution searches the network built so far from the first end of each pipe before laying it. On the in-order line that end is always the built one, so each search walks every valve laid so far, about 5 times 10^9 steps in all. Measured on a cold JVM: reference 18 ms and 15 ms; naive timed out on both at a limit raised to 10,000 ms (more than 20 s on the in-order line in an earlier run).

The second large test closes a gap the review found. A brute force that searches from the second end of each pipe, and reuses one visited-stamp array instead of allocating one per search, passes the in-order line in 75 ms. On the mixed-direction far-end line it timed out at a limit raised to 30,000 ms, well past the 4,500 ms line.
