# Grader notes: Letter Combinations of a Phone Number

Strings are sorted before comparing, because any order is allowed; a string listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample, a single digit, a repeated four-letter key (`77`: 16 strings including `pp`; a keypad that gives 7 only three letters, as the formula "three letters per key from `a`" does, fails), the keys after 7 (`8` and `39`: that formula shifts every key from 8 on by one letter and fails), no digits (the answer is an empty list; a version that returns a list holding the empty string fails), and four inputs checked by count: the test multiplies the key sizes itself, then checks that every string has one letter from each digit's key in order and appears once, so the right count means none is missing (`2345`, `6789`, `97979` with 1,024 strings, `22222`).

No naive solution: time is not graded separately for this question (ADR 0008). Every correct approach writes every string, up to 4^5 = 1,024 of them, so the walkthrough's brute force, which counts through the combinations like an odometer, costs the same as the reference. The largest test has a generous 2,000 ms limit only to catch a runaway loop.
