# Grader notes: Generate Parentheses

Strings are sorted before comparing, because any order is allowed; a string listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample (n = 2), four pairs written out in full (14 strings), no pairs (the answer is a list holding the empty string; a version that returns an empty list for n = 0 fails, and the statement states this deviation from the usual version, where n starts at 1), one pair (a version that keeps every string with equal numbers of each bracket, without checking that no prefix closes more than it opened, also lists `)(` and fails), and n = 3 and 5 to 8 checked by count: the test counts the balanced strings itself with the Catalan recurrence (a balanced string is `(` inner `)` rest), then checks that every returned string has length 2n, is balanced and appears once, so the right count means none is missing.

No naive solution: time is not graded separately for this question (ADR 0008). The walkthrough's brute force builds all 2^(2n) strings and keeps the balanced ones. In a cold scratch run it took 15 ms for n = 8 against about 1.3 ms for the reference, and 153 ms against about 3 ms for n = 10; the timing rule needs the naive to take at least 36 times as long as the reference (limit at least 8 times the reference, naive at least 4.5 times the limit), n = 8 is far short of that, and at n = 10 the answer (16,796 strings) is no longer small while the test's own checking of every string, which counts against the reference's time, eats most of the 50-fold gap. The largest test (n = 8, 1,430 strings) has a generous 2,000 ms limit only to catch a runaway loop.
