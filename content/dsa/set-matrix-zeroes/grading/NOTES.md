# Grader notes: Set Matrix Zeroes

Deviation from the classic version: the grid can be up to 1000 x 1000 (the classic stops at 200 x 200), so that the timed test can tell the brute force from the reference; readings are any `int`, as in the classic. The statement fixes what "in place" means: the method is `void`, and when it returns, the array that was passed in must hold the cleared grid. Every test checks the caller's own array, row count, row lengths and each cell, so clearing a copy and assigning it to the parameter fails every test but the one with no failed sensor (fails 10 of 11). The result is a single grid, so there is only one correct output.

Tests cover: the sample (a 4 x 5 grid with two failed sensors, a 2 x 5 grid with a 0 in the first row, and a 4 x 2 grid with a 0 in the corner and the smallest and largest `int` among its readings); grids with no failed sensor (1 x 1, 2 x 6, 6 x 1), which must stay as they are; single cells, rows and columns (`[[0]]`, a row of 6, a column of 5, and a 1 x 1000 row and a 1000 x 1 column whose only 0 is at one end); a 0 only in the first row; a 0 only in the first column; zeros in the other corners; readings cleared by one 0 that must not clear their own rows and columns; -1 and the smallest and largest `int` as surviving readings; a grid where every row fails, and an all-zero grid; 300 seeded random grids of 1 to 12 rows and columns with about one reading in ten failed and a few readings of -1, 1 and the `int` limits, checked against flags built in the test; and the timed test below.

The traps the walkthrough and hints name, each run as a scratch variant: clearing rows and columns while still scanning for zeros (fails 8 of 11); marking cells to clear with a sentinel such as `Integer.MIN_VALUE` (fails 4) or -1 (fails 5), which a real reading can equal; the corner cell holding the flags of both row 0 and column 0 (fails 5); clearing from the top row down, which overwrites the first-row flags before they are read (fails 5); clearing each row's first-column cell before its other cells (fails 5); and the copy assigned to the parameter (fails 10).

Timing: `largestGridsWithMostSensorsFailed` has a limit of 500 ms (3x is 1,500 ms). It clears two 1000 x 1000 grids: in the first every sensor has failed except those in row 500 and column 700, so only the reading where they cross survives; in the second every sensor has failed except those in rows 0 to 9 or columns 990 to 999, so a 10 x 10 corner survives. In both, almost a million sensors have failed, so the brute force clears a row and a column about a million times. The reference took 30 to 48 ms over six cold runs. The naive solution is the walkthrough's Brute force, wiping from a copy of the grid, at 4,451 ms with the limit raised 20 times; a brute force that collects the zeros first and wipes them in reverse order fails only this test, as does the naive. The walkthrough's Better, a flag per row and per column, is O(m·n) like the reference and passes.
