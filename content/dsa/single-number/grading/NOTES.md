# Grader notes: Single Number

Same rule and value range as the classic version (values between -3 · 10^4 and 3 · 10^4, every value twice except one), but arrays of up to 10^5 values instead of the classic 3 · 10^4, so that the brute force can be timed out by a wide margin; the value range still has room for 50,000 pairs. Only the class and method names are otherwise this pack's. The classic asks for constant extra memory as a requirement. No test can measure the memory a solution uses, so the statement asks for it in the follow-up instead, and a set or a count array passes. The answer is a single `int`, so there is only one correct output.

Tests cover: the sample (`[12, 5, 10, 12, 10]`; `[0, 40, -7, 3, 40, 0, 3]`, where no copy is next to its partner and the lone value is negative; `[-30000]`, a single value at the lower limit); more single values (30000, 742, -58); copies far apart with the lone value in the middle, first, last and in between; 0 as the lone value, arrays of negative values only, and 6 and -6 as different values; values at both limits; arrays whose lone value is the smallest or the largest, so that it comes first or last once sorted; 500 seeded random arrays of 1 to 601 values, fully shuffled, whose answer is known by construction; and the timed test, 16 arrays of 99,999 values, the largest odd length allowed. In those, the first copies come in one random order and the second copies in another, so each copy is far from its partner, and the lone value sits at a random position in the middle third.

The traps the walkthrough and hints name, each run as a scratch variant: comparing neighbours without sorting fails 7 of 8 tests; a count array indexed by the value itself fails all 8 with an index out of bounds at the first negative value; sorting and comparing pairs of neighbours with no answer for a lone value that comes last fails 7. Correct variants that pass: the walkthrough's set, a flag array shifted by 30,000, sorting a copy and comparing pairs, and twice the sum of the distinct values minus the sum of all values.

The naive solution counts each value's copies with a full scan and times out on the timed test at the limit and at 3x. The limit is 500 ms, so 4.5 times it is 2,250 ms. The reference took 22 to 27 ms over seven cold runs (an eighth of the limit is 62 ms), almost all of it building the arrays, and the naive 21,390 ms with the limit raised 80 times. The slower variants the walkthrough describes, a scan that stops at the first other copy and one that skips copies already matched, were run in every direction, each taking at least 3 times the 2,250 ms (times with the limit raised 20 times, so a variant still running at 10,000 ms timed out there):
- the full count from the end of the array, and a stopping scan with both loops from the front, both from the back, or wrapping round from the next position: still running at 10,000 ms;
- a stopping scan with the outer loop from the front and the inner one from the back: 9,120 ms; the outer loop from the back and the inner from the front: 7,660 and 7,758 ms;
- a stopping scan that looks right of each value first and then left of it: 8,719 ms;
- marking each partner found and searching only to the right of a value: still running at 10,000 ms, or 8,102 to 8,505 ms when the search does not skip marked copies;
- the same searching only to the left: still running at 10,000 ms, or 7,025 to 7,168 ms without skipping, the fastest of all.

The layout is what keeps every direction slow: whichever end a scan starts from, it passes at least a third of the array before it reaches the lone value, and the copies are placed so that each value's search for its partner, from either side, costs a quarter of the array or more on average. The walkthrough's set took 115 ms and sorting a copy 158 ms, both well inside the limit; a flag array shifted by 30,000 took 29 ms and the sum trick 277 ms.
