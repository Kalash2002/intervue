# Grader notes: Single Number

Same sizes and rule as the classic version (1 to 3 · 10^4 values between -3 · 10^4 and 3 · 10^4, every value twice except one); only the class and method names are this pack's. The classic asks for constant extra memory as a requirement. No test can measure the memory a solution uses, so the statement asks for it in the follow-up instead, and a set or a count array passes. The answer is a single `int`, so there is only one correct output.

Tests cover: the sample (`[12, 5, 10, 12, 10]`; `[0, 40, -7, 3, 40, 0, 3]`, where no copy is next to its partner and the lone value is negative; `[-30000]`, a single value at the lower limit); more single values (30000, 742, -58); copies far apart with the lone value in the middle, first, last and in between; 0 as the lone value, arrays of negative values only, and 6 and -6 as different values; values at both limits; arrays whose lone value is the smallest or the largest, so that it comes first or last once sorted; 500 seeded random arrays of 1 to 601 values, fully shuffled, whose answer is known by construction; and the timed test, 50 arrays of 29,999 values, the largest odd length allowed. In those, the first copies come in one random order and the second copies in another, so each copy is far from its partner, and the lone value sits at a random position in the middle third.

The traps the walkthrough and hints name, each run as a scratch variant: comparing neighbours without sorting fails 7 of 8 tests; a count array indexed by the value itself fails all 8 with an index out of bounds at the first negative value; sorting and comparing pairs of neighbours with no answer for a lone value that comes last fails 7. Correct variants that pass: the walkthrough's set, a flag array shifted by 30,000, sorting a copy and comparing pairs, and twice the sum of the distinct values minus the sum of all values.

The naive solution counts each value's copies with a full scan and times out on the timed test at the limit and at 3x. The limit is 400 ms; the reference took 24 to 32 ms over six cold runs, almost all of it building the arrays, and the naive 6,119 ms with the limit raised 20 times. The slower variants the walkthrough describes time out as well, each at 4.5 times the limit or more: the same scan from the end of the array (5,879 ms), a scan that stops at the first other copy, from the front (5,760 ms) and from the back (6,885 ms), and one that marks each partner it finds and searches only to the right (2,708 ms) or only to the left (2,823 ms). The walkthrough's set took 96 ms and sorting a copy 147 ms, both inside the limit.
