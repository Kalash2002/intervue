# Grader notes: Maximum Subarray

The rules are the classic ones: up to 100,000 entries from -10,000 to 10,000, and a run has at least one day. The constraints also state the range of every run's total, -10^9 to 10^9, which follows from the other two and means an `int` holds every total; the largest test answer is exactly 10^9. There is one answer, a number, so no tie rule is needed.

Tests cover: the sample; a losing day inside the best run (`[6,-5,7]` gives 8 and `[7,-3,2,-1,6,-2,4]` gives 13, the whole ledger, where cutting the ledger at every loss gives 7 for both; the walkthrough names that wrong greedy, and it also fails the sample, the random test and the second long test); every day a loss (`[-7,-1,-3,-1]`, three -4s, two -10,000s; starting the best at 0, or resetting the run to 0 before taking the best, gives 0 here and on Example 3 and `[-9]`, and so does the lowest-balance pass when it updates the low before using it, which the walkthrough warns about); one day (`[5]`, `[-9]`, `[0]`); zeros between losses (`[0,-3,0]` and `[-2,0,-1]` give 0); the best run at either end (`[-4,1,7]` gives 8, `[2,-5,3]` gives 3, `[7,1,-9,3]` gives 8); 300 seeded random ledgers of 1 to 12 entries from -9 to 9, checked against adding up every run in the test; and two ledgers of 100,000 days. The first is 10,000 every day (answer 10^9). The second repeats 10,000, 10,000, -9,999, so every three days add 10,001, with day 0 a loss of 10,000 that the best run leaves out: days 1 to 99,999 give 1 + 33,332 × 10,001 + 10,000 = 333,363,333. Adding up only the gains fails the sample and four other tests.

The two long tests have a limit of 200 ms each (3x is 600 ms). The reference, the best run ending on each day (Kadane's algorithm), finishes each in under 20 ms on a cold JVM, most of it building the input. The naive solution is the brute force, every first day extended to every last day with a running total; it takes about 3 s on each, past the limit and 3x. The walkthrough's Better, the lowest balance so far, is O(n) like the reference and passes. The walkthrough names no slower variant besides the brute force.
