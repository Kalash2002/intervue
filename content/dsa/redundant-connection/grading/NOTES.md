# Grader notes: Redundant Connection

Tests cover: the sample (a loop whose last cable is listed reversed, and a later cable that is a bridge, not spare); a ring of three buildings, twice, so the answer must keep its listed order (`[0, 2]`, not `[2, 0]` reordered); a loop that does not touch building 0; loop cables scattered among other cables; a bridge between two buildings with three cables each, listed last (a solution that picks the last cable whose ends both have two or more cables returns it and fails); one loop through 100,000 buildings, whose spare cable is the last one listed (a recursive search, or a recursive find over unbalanced groups, overflows the stack here); and a timing case of 20,000 buildings where a loop of three is listed first and a long line follows.

The large timing test has a limit of 600 ms (3x is 1,800 ms). The naive solution removes cables from the end and searches from building 0 each time; every cable of the line is a bridge, so it runs about 20,000 searches before reaching the loop. Measured on a cold JVM: reference 1 to 2 ms, naive 6.6 s. The 100,000-building test has a limit of 1,000 ms; the naive passes it quickly because the spare cable is the last one it tries first.
