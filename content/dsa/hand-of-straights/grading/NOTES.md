# Grader notes: Hand of Straights

The hand may hold up to 100,000 cards (the classic version allows 10,000) so that the O(n²) brute force can be timed out; numbers run from 0 to 10^9 and `size` from 1 to the hand's length, as in the classic. The answer is `true` or `false`, so no tie rule is needed. The largest number a straight asks for is below 10^9 + 10^5, so `int` arithmetic is safe; the first timed test reaches 10^9.

Tests cover: the sample (Example 1 needs the smallest-first start and two straights started together at 31; Example 3 is three copies of one number); a straight started above the smallest card (`[23,27,22,25,24,26]` and `[13,15,12,14]`, both true; starting a straight at the first card not yet used, in the order dealt, the wrong greedy the walkthrough and Level 1 hint name, says false here and fails 7 of the 10 tests, Example 1, the blocks test, the repeats test, the size test, the random test and the first timed test among them); blocks of the sorted hand (`[31,30,31,30]` with size 2 and `[41,42,40,41,42,40]` with size 3, both true; cutting the sorted hand into blocks of `size`, also named, fails these, Example 1, `[7,8,7,8,9,9]`, the random test and the first timed test); a gap (`[3,5,4,7,6,9]` and `[100,102]`, false); cards left over (`[20,21,21,22,22]` with size 2, false); repeats (`[50,50,51,51]` with size 4 false, `[7,8,7,8,9,9]` with size 3 true, `[7,7,8,9]` with size 2 false, and `[5,5,6,7,7,8]` with size 2 false, where two straights start at 5 but there is one 6: checking only that the next number has some copy left, rather than as many as the straights starting, says true there, on the random test and on the second timed test); size 1 and size equal to the hand (`[1000000000,0,1000000000]` and the single card `[6]` with size 1, true; `[12,10,11]` true and `[12,10,14]` false with size 3; `[0,1000000000]` with size 2, false); 300 seeded random hands of 1 to 12 cards numbered 40 to 48, half dealt as straights on purpose and shuffled, a third of those with one card changed (the numbers and the seed keep every hand away from the classic samples' values and shapes), checked in the test by a search that puts the first card left into every straight that could hold it; and two timed hands. The first holds 33,333 copies each of 999,999,998, 999,999,999 and 1,000,000,000, shuffled, with size 3: true. The second holds 50,001 sevens and 49,999 eights, shuffled, with size 2: false, but only after the pairs 7, 8 have used up every 8, so a search from the smallest card and one from the largest both do almost all the work before they fail, and the card count divides evenly.

Both timed tests have a limit of 200 ms (3x is 600 ms). The reference, counting in a hash map and sorting only the distinct numbers, takes 14 to 19 ms on the first and 5 to 6 ms on the second on a cold JVM, most of it counting the cards. The naive solution is the walkthrough's brute force, the sorted array with a flag per card: every search walks past about 33,000 or 50,000 cards, so it takes about 2.2 s on the first and 1.8 s on the second, past the limit and 3x. Its mirror, which starts each straight at the largest card left and searches downwards, and the same search done by removing cards from a sorted `ArrayList`, time out on both. The walkthrough's Better, the counts read off the sorted hand, is O(n log n) against the reference's O(n + d log d) for d distinct numbers, a log factor at most, and passes (11 to 14 ms and 4 to 6 ms); so does a sorted map of counts taking one straight at a time.
