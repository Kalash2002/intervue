# Grader notes: Combination Sum II

Results are compared after sorting each combination and then the list, because any order is allowed; a combination listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample (two equal 2s that each pair with the 6), all values equal (`[5, 5, 5]` with target 10: a version that skips a value equal to the previous one at every depth, `i > 0` instead of "not the first choice at this step", loses `[5, 5]`), no combination, each position used at most once (`[3]` with target 6 must give nothing; a version that lets a position repeat returns `[3, 3]`), repeats that are not side by side (`[1, 7, 1, 6, 1]`: a version that skips equal neighbours without sorting lists `[1, 1, 6]` several times), the limits, and three inputs checked by count: the test counts the distinct combinations itself with a table that takes each value 0 to (its copies) times, then checks that every returned combination adds up to the target, uses no value more often than `candidates` holds it and appears once, so the right count means none is missing.

The two large inputs are 80 values, ten each of 1 to 8 in seeded shuffled order, with target 32 (2,754 distinct combinations), and 80 copies of 1 with target 32 (one combination). The limit is 1,000 ms (3x is 3,000 ms). The naive solution, the walkthrough's brute force, takes or leaves each position, stops a branch only when a value overshoots, and removes repeats with a set; equal values at different positions make it explore every choice of positions that stays under the target (on 80 ones, every choice of up to 32 of the 80 positions), and it did not finish in 20 s in a scratch run. The reference took about 3 ms on the first large input in the same scratch run.
