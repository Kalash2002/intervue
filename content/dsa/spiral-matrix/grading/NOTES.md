# Grader notes: Spiral Matrix

Changed from the classic version: the floor can be up to 100 x 100 (the classic allows 10 x 10) and readings run from -1000 to 1000 (the classic allows -100 to 100), so the largest tests have 10,000 readings. The statement also says `grid` must not change, and every test checks that. The walk is fixed (start top left, go right, turn clockwise), so there is exactly one correct list.

Every test compares the returned list with the expected one reading by reading and then by its size, so a list with the right readings followed by extra ones, or one cut short, fails; it never compares the printed lists. It also checks that the list is not null and that `grid` holds the same values after the call as before.

Tests cover: the sample (a 4 x 5 floor, a 5 x 2 floor, and a single column of 3); a single row and a single tile; single columns of 4 and of 2 (with equal readings); a 5 x 7 floor whose last part is a middle row of 3 tiles; a 7 x 5 floor whose last part is a middle column of 3 tiles; a 5 x 5 floor that ends in its centre; floors 2 x 6 and 6 x 2; a 4 x 6 floor of equal readings; the largest floors, 100 x 100, 1 x 100, 100 x 1, 100 x 99 and 99 x 100, checked against the walk built in the test; and 300 seeded random floors from 1 x 1 to 12 x 12, checked the same way. Hand-written floors avoid the classic shapes (3 x 3, 3 x 4 and 4 x 4).

The traps the walkthrough names, each run as a scratch variant: the ring-by-ring walk with no guard before the bottom and left sides, which walks a leftover row or column twice (fails 7 of 10); the same walk guarding the bottom side only, which still walks a leftover column twice (fails 5); stopping while the boundaries still enclose a single row or column (`top < bottom && left < right` as the loop condition, fails 8); marking cleaned tiles in `grid` itself (fails all 10 on the grid check); and turning the wrong way, down first (fails 7). The walk that remembers cleaned tiles in a separate array and the guarded ring-by-ring walk both pass.

No naive solution: time is not graded separately for this question (ADR 0008). Every approach has to list each of the m × n readings once, so the brute force, the walk with a separate record of cleaned tiles, is O(m × n) like the reference and only uses more memory; with at most 10,000 tiles there is no slower correct approach worth timing. The tests keep the default limit.
