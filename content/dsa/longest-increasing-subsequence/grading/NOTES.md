# Grader notes: Longest Increasing Subsequence

The array may hold up to 200,000 values from -10^9 to 10^9 (the classic version allows 2,500 values from -10^4 to 10^4). At that size the O(n²) table, the walkthrough's Better approach, is graded as too slow: the statement's sizes, the timed tests and the walkthrough all say so, and the O(n log n) smallest-end list is what passes.

Tests cover: the sample; equal values that must not extend a pick (`[2,2,4,4,8,8]` gives 3, `[-1,-1,-1,0]` 2, `[3,3]` 1; searching for the first end greater than the value, which allows equal values, gives 6, 4 and 2, and fails Example 2 with 5); picks that skip positions (`[3,1,4,2,5]` gives 3 and `[10,1,11,2,12,3,13]` gives 4; the longest rising run of neighbours gives 2); taking the next larger value at once (`[2,9,3,4,5]` gives 4, which greedy from every start gets as 3; `[9,1,2,3,10]` gives 4, where starting at the first value gives 2; `[5,6,7,1,2]` gives 3, where starting at the smallest gives 2); a single value; values at the limits (`[1000000000,-1000000000,0,999999999]` gives 3); 300 seeded random arrays of 1 to 12 values from 0 to 7, checked against a search in the test over every set of positions; and three arrays of 200,000 values: 400 falling blocks of 500, each block above the one before (400, one value per block); a rise in equal pairs from -10^9 (100,000, one of each pair; the non-strict search gives 200,000); and the evens 0 to 199,998 rising, then the odds 199,999 down to 1 (100,001: all the evens, then 199,999, since the odds fall).

The three large tests have a limit of 300 ms each (3x is 900 ms). The reference finishes each in about 10 to 15 ms. The naive solution is the walkthrough's Better approach, the O(n²) table, because that is the slower approach the constraints are set to rule out; it takes about 27 s per large test, far past the limit and 3x. The walkthrough's Brute force, every rising pick from every start, is exponential: it times out on the falling blocks and overflows the stack on the two long rises, so it fails all three. Walking the list of ends one by one instead of the binary search is O(n × answer): from the front it takes about 2.3 s and 2.1 s on the two long rises, and from the back, which is quick on a plain rise, it still takes about 1.2 s on the evens-then-odds test, where every odd value lands in the middle of a list 100,000 long. `Arrays.binarySearch` on the list, which is strictly increasing, passes.
