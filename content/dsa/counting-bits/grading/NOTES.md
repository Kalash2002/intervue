# Grader notes: Counting Bits

Same size and rule as the classic version (`0 <= n <= 10^5`, an array of `n + 1` counts); only the class and method names are this pack's. Each table is compared by its length first and then entry by entry, so a table one entry short fails with a message about its length. The answer is a single array, so there is only one correct output.

Tests cover: the sample (`n = 10`, `n = 16` and `n = 0`, the forced smallest input, whose table is `[0]`); `n = 14` written out and `n = 31`, which end on numbers with several 1 bits; every table from `n = 0` to `n = 300`; powers of two and one below them, 63 and 64, 1023 and 1024, 4095 and 4096, 65535 and 65536; the largest table, `n = 100000`; and four other large sizes (99999, 77777, 31416, 13469). Every table except the three of the sample and `n = 14` is checked against the test's own table, which counts each number's bits one at a time, and that table is spot-checked against values worked out separately (16 for 65535 and for 98303, 10 for 99999, 6 for 100000, 1 for 65536).

The traps the walkthrough and hints name, each run as a scratch variant: an array of `n` entries instead of `n + 1` fails all 6 tests on its length; setting entry 1 before the loop fails the sample and the run of every table up to 300 with an index out of bounds at `n = 0`; and the Better's power of two moved up after the entry is filled instead of before fails all 6. Two more were run: `ones[i - 1] + (i & 1)` and `ones[i / 2] + 1` each fail all 6. The walkthrough's three approaches pass, and so do `ones[i & (i - 1)] + 1` and `Integer.bitCount` for each entry.

No naive solution: time is not graded separately for this question (ADR 0008). The brute force, counting each number's bits, is O(n log n) against the reference's O(n), but at `n = 10^5` that is about 17 steps per entry against one. Measured on `n = 100000` in a scratch run, the brute force took about 3 ms on its first call and 1.1 ms per table once warm, the reference 1.2 ms and 0.12 ms: a ratio of at most 9, far from the 36 the timing rules need (reference within an eighth of the limit, naive over 4.5 times it), and a brute force that counts with `Integer.bitCount` is as fast as the reference. The tests keep the default limit; the reference took 1 to 3 ms on the largest table and 11 to 12 ms on the sample, the first test of the JVM, over six cold runs.
