# Grader notes: Clone Graph

`GraphNode.java` is read-only and shared by the tests: `of` builds a graph from values and adjacency lists, `reachable` lists the nodes in breadth-first order, and `deepCopyProblem` walks the input and the copy in lockstep and reports the first difference: a copy node that is an input node, a different value, a different list size, a neighbour that is not the copy of the input's neighbour at the same position, or two input nodes sharing one copy. Every test also checks that no input node's neighbour list changed.

Tests cover: the sample (a triangle with a two-node tail, two nodes holding 6 and two holding 2, neighbour lists not sorted), a single node with no neighbours, `null`, graphs where every node holds the same value (a path of three and a star of four: a version that maps nodes by value merges them and fails), two nodes, five nodes all joined to each other, neighbour lists in an order that is not sorted, a chain of 100,000 nodes (a recursive copy overflows the call stack here and fails), and a seeded random connected graph of 100,000 nodes and about 200,000 connections with only five distinct values.

No naive solution: time is not graded separately for this question (ADR 0008). The walkthrough's brute force, parallel lists with a linear search, is quadratic: in the test it took 13,013 ms on the chain and 9,507 ms on the random graph, while the reference plus the test's own building and checking took 269 to 270 ms and 537 to 600 ms. The building and the identity-map check cost about as much as the copy itself, so no naive can meet the timing rule's factor. The limits on the two large tests are 60,000 ms, well above the brute force, so a correct quadratic solution passes on any reasonable machine and the limits only stop a runaway solution.
