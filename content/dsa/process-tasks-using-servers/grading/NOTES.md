# Grader notes: Process Tasks Using Servers

Tests cover: both samples, one machine, more machines than jobs with a weight tie (lower number first), jobs that wait and then take machines in arrival order, a machine that frees at the very second a job arrives, identical machines, a heavy machine used only while the light one is busy, a case where one machine stays busy until second 3,000,000,000, past the `int` range (an `int` clock sees it as free and gives job 5 to machine 1 instead of machine 0), and a large case of 200,000 jobs on 150,000 machines whose weights are a permutation of 1 to 150,000. There the first 150,000 jobs take the machines in weight order and each later job `j` takes the machine that job `j - 150,000` used, because that machine frees at exactly second `j`; the expected array is built from that rule without running any assignment code.

The naive solution scans every machine for every job. Measured with a cold JVM on the large test: reference 262 ms, naive 21.1 s, limit 3,500 ms (reference 13x under the limit, naive 2.0x past the 3x line of 10,500 ms). The reference uses a heap of free machines and a heap of busy ones.
