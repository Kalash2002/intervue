# Grader notes: N-Queens

The list of placements is sorted before comparing, but each placement is compared row by row as returned; a placement listed twice stays in the compared list twice, so repeats fail. Tests cover: the sample (n = 6, four placements), boards with no placement (n = 2 and 3: the answer is an empty list), the one-square board, and n = 4, 5, 7, 8 and 9 checked by count: every returned board must have n rows of n squares with one queen each, no two queens in a column or on either diagonal, and no board listed twice, and the count must match the known numbers (2, 10, 40, 92, 352), so the right count means none is missing. A version that checks only one diagonal direction places attacking queens on n = 4 and 5 and fails `bothDiagonalsCount`; a version that forgets to free a column or diagonal on the way back finds too few placements and fails the sample.

The large test is n = 9 (352 placements). The limit is 400 ms (3x is 1,200 ms), wide enough that the reference keeps verify's headroom on a loaded machine. The naive solution, the walkthrough's brute force, puts a queen in every column of every row (9^9 = 387,420,489 boards) and checks each finished board: 2,936 ms in a cold scratch run. The reference skips a square as soon as an earlier queen attacks it: about 2 ms in the same run, and 18 to 25 ms for the whole test including the test's own checks of all 352 boards. The naive takes about 145 ms on n = 8, inside the default limit of the untimed test.
